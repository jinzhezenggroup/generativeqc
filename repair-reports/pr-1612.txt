## Summary

Continue the WB97M-V CUDA stationary residency stack on top of #1611 by removing per-tile coordinate uploads.

#1581 already retains the exact CUDA-generated molecular-grid points/weights in the native KS owner. The force-side compiler `CudaGrid` was still receiving `state.grid.points[begin:end]` from the detached host snapshot and copying those coordinates back to the same device for every AO/grid tile.

This stack:
- exposes the immutable native resident molecular-grid pointers through the exact KS snapshot token;
- adds a device-point execution route to the existing CUDA grid owner;
- reuses the same AO/feature kernels with a borrowed device point pointer;
- makes `GridTaskView.points` publish the exact point source used by the task;
- removes `points[begin:end]` from the WB97M-V stationary scheduler;
- records `grid_point_source = exact-native-resident-grid` and `grid_point_h2d_bytes = 0`.

## Ownership / correctness

No new point/grid mathematics is introduced. Host-point execution remains unchanged for generic callers.

The resident grid bridge:
- validates the exact current KS token before publication;
- requires the same CUDA device as the final-state owner;
- retains native grid lifetime through the prepared KS owner;
- validates the token again in Python after the private ABI returns.

The device-point CUDA route validates device residency and tile bounds and keeps the existing deferred same-stream error propagation. AO/XC and moving-grid geometry consume the borrowed point pointer directly.

Depends on #1611 -> #1610 -> #1609. Retarget in order after parents land; do not merge out of order.
