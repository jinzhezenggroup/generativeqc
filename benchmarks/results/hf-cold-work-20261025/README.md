## Complete endpoint observations

The campaign contains **75 populations / 300 energy-and-force calls**:
30 baseline, 30 candidate and 15 freshly measured GPU4PySCF populations.
HF covers Direct/DF, 3/12/48/96 atoms and native Standard/Fast. Seven additional
DF functionals cover 48 atoms in both native profiles. Each population has one
cold call and three warm calls from its own frozen cold density. The warm median
and full range appear in the timing table. Small differences are observations,
not statistical significance claims.

Fast-HF retains a completed Standard FP64 endpoint instead of launching a second
strict audit solely because its initial seed was cold. Explicit TargetAccuracy
requests still audit. DF-RHF force finalization retains the original determinant
only after a fresh physical-Fock projector check and the existing reconstruction,
trace/idempotency, orthogonality and commutator gates; its Pulay weight remains
`D F[D] D / 2`. Original force-frame reuse keeps its occupied-response lease.
Forced/reference/energy-only and rejected-probe correction routes remain bounded
and canonical.

Large method-authorized singleton physical DF sources can select existing
`packed-single` storage above a 1-GiB dense-value floor, under the same allowance
and only with full requested occupied capacity. Explicit policies, small sources,
batch/UHF/general-density boundaries and resource fallbacks remain intact.

The packing-only source-matched ablation reduces 48-atom Standard DF-HF cold time
from 14.735 s to 4.486 s while retaining 23 Fock builds; adding the retained-frame
proof reduces it to 3.456 s and 11 Fock builds. B3LYP packing-only is 7.931 s,
consistent with the final 7.858 s observation. The Python-only change uses the
unchanged baseline native binary and removes the extra Fast-HF solve at 48/96
atoms. These ablations remain separate from the main populations.

Common independent direct-reference gates remain energy 1e-5 Eh/atom, maximum
force 1e-4 Eh/Bohr, and RMS force 3e-5 Eh/Bohr. Dense DFT reference stability and
CPU/GPU spot agreement are recomputed at quarter gates. Original reference
identities and audited reuse contracts are retained; four HF CUDA direct
references were freshly recomputed. Reference densities never seed production.

All failures are the preexisting DF-HF fitting energy error relative to direct

the largest before/after energy change is 8.15e-13 Eh/atom and the largest

separately and do not replace the dense independent accuracy gates.

Validation includes device final-state and resource/planner native tests,
521 Python tests,
three explicit audit-isolation CUDA tests, and 18 moved-geometry/property calls
(HF/PBE/B3LYP, Standard/Fast, E+F → E → E+F). Each moved force is compared with
an independent GPU4 DF calculation. Device final-state memcheck reports zero
errors. Exact suite outcomes, skips, original failures and reruns are retained.

The first broad density-fitting native run hit an existing J-only work-count
assertion; the unmodified baseline reproduces the same failure. That assertion
required an old fitted-panel call count, rejecting the already optimized
charge-first path. Its replacement preserves independent force parity and bounded
panel coverage, and tightens the semantic work bound to at most one full raw
source's regenerated bytes. The repaired test is compiled against the same
frozen candidate library; production code remains the measured candidate SHA.

## Measurement and reproduction

Cold includes calculator construction, preparation, SCF, analytic forces and host
export with installed/prebuilt native code. Process startup, offline references,
compilation and intrusive profiling are outside endpoint timing. Thread settings
are OMP/OpenBLAS/MKL=1, with four allocated CPU cores. Source archives and every
archived source file were verified; native binary hashes, AOT libraries,
compiler commands and cache statistics are retained in provenance. Compilation
uses verified sccache 0.16.0 with the existing cache, CUDA 12.9, sm_120 and GCC 13.

Both engines use spherical def2-SVP (def2-mTZVPP for r2SCAN-3c), identical
geometries/state and frozen reference-selected auxiliary tables. Stock level-3
XC/VV10 grids and each engine's own convergence policy remain in use; full
moving-grid force response is enabled. r2SCAN-3c includes D4/gCP in both endpoints.
Native ωB97M-V uses fitted full-range plus exact long-range exchange; GPU4 fits
both. Each sample retains executed settings, grids, precision/audit history and
work counters. `GENERATIVEQC_CUDA_XC_SPATIAL_ORDER=2` and
`GENERATIVEQC_SCF_VALIDATION_GEMM=1` match the prior README protocol.

The original first baseline launcher recorded the unambiguous short SHA
`194f12d78`. Raw receipts remain unchanged. The offline qualifier expands it in
a derived copy, retaining `recorded_source_revision` and a canonical
`raw_receipt_sha256` binding; no timing/scientific value is rewritten.

```bash
PYTHONPATH=python:. python benchmarks/results/hf-cold-work-20261025/reproduce.py \
  --output .artifacts/hf-cold-work-replay
```

This replays every numerical gate, before/after delta, same-model GPU4 comparison,
moved-geometry check and timing table from full-precision retained receipts.
`execution.json.xz` retains exact executed scripts/commands and outcomes; adjust
historical installation paths when rerunning on another machine. All GPU
reexecution must use a compatible finite `srun` allocation and preserve its
assigned visibility. Profiling receipts and diagnostic ablations are separate.

## Remaining work

48-atom HF now beats the measured GPU4 cold endpoint in both Direct and DF.
96-atom Direct HF and DF-HF still lag. The 96-atom DF profile attributes about
6.49 s to source preparation (4.54 s metric projection, 1.94 s raw generation),
7.05 s to SCF, and 4.19 s to finalization after the repair. Those costs require
further producer/contraction work. These sampled latency observations do not
establish universal or statistically interleaved performance leadership.
