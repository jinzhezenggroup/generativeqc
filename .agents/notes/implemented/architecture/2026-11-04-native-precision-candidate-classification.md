# Decision: native completed application-precision candidate classification

Status: implemented
Date: 2026-11-04

## Problem

Native execution order, completed-work predicates and observable comparison
still depended on a Python classifier for gradient receipt interpretation and
the final choice between qualification and an independent audit. Keeping a
portable classifier would leave two production policy authorities. Complete
r2SCAN-3c admission also resolved a compiler MethodIR inside runtime comparison.

## Decision

`generativeqc_precision_candidate_query_v1` consumes copied categorical facts,
attempted-work counters and the existing public native precision records. It
reuses the shared native completed-work/returned-state/Standard predicates,
interprets only incumbent gradient receipt schemas and owners, binds corrected
models against the native catalog's exact restricted r2SCAN-3c identity, and
selects one publication disposition and ordered reason bits. The catalog uses
the canonical `r2scan-3c-rks` entry, not the frontend's alias `r2scan-3c`.

Python transports diagnostics and typed correction facts and presents the native
receipt. It does not retain gradient qualification tables, correction admission
or shortcut predicates in its candidate classifier. Constructors and scalar/
prepared execution require the selected protocol before electronic/fleet work.
Missing/refused/malformed protocol never chooses portable policy. The explicit
target fact is snapshotted before calling an owner so a mutated request cannot
forge no-audit coverage.

## Invariants

- Explicit targets always audit, even with recognized gradient qualification.
- Retain all incumbent profile, schema/owner, attempted geometry/weighted work,
  strict final-state, complete census, budget and correction requirements.
- Missing mixed-stage counts cannot turn their native unknown sentinel into a
  positive strict-XC warmup count. Its presence is transported separately.
- Qualification remains independent historical evidence, never a per-system
  error estimate, new method/provider capability or replacement physical proof.
- Native work predicates are shared, not copied into another classifier. The
  metadata query allocates nothing, executes no electronic work, retains no
  input and publishes only after all reads. Invalid input preserves output.
- Numerical kernels, thresholds, forces, observable allowances and retry/audit
  order are unchanged. No production compiler resolution is needed for this
  correction identity check.

## Boundaries and rejected alternatives

Moving actual gradient construction/provider/basis/budget eligibility into this
receipt interpreter would conflate a policy cutover with a new scientific
execution owner. Those gradient producers, initial prepared fleet execution,
independent candidate/auditor history and resource leases remain explicit
separate owners. A caller-supplied canonical identity, a display-name allowlist
or fallback to the old Python classifier would defeat native authority and are
not retained. This is not an autonomous installed native precision endpoint or
SDK/CLI/Python parity.

## Evidence and revisit conditions

Compiled public ABI and transport tests cover all incumbent schema/name/owner
domains, explicit target priority, complete correction source failures,
missing/unknown counters, weighted work, reason precedence, malformed/overlapping
descriptors, atomic failures, concurrent queries and missing/refused/forged owners.
Existing facade/prepared tests retain route, cleanup and seed independence
contracts. Physical pinned HF E/F and KS finite-difference acceptance and
complete-endpoint matched CPU timing/work remain required; detached receipts
are not real-GPU qualification. Full #2227 R1–R6 remain incomplete.

Revisit when actual prepared gradient producers and seed/fleet transactions can
move to shared native owners with their independent physical, lifetime,
resource/work and complete-endpoint performance acceptance.
