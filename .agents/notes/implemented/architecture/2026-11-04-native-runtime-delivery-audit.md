# Decision: separate runtime delivery snapshots from the original call graph

Status: implemented
Date: 2026-11-04

## Problem

The #2227 source inventory retains a pre-cutover source revision. Its historical
CPU/CUDA force rows still describe Python stationary controllers, while current
prepared dispatch first queries native per-item property admission. Automatic
CUDA force refusal cannot enter that compatibility route. The native CLI also
already supplies a scoped resource command, and a dedicated WB97M-V CUDA
second-order endpoint exists. Reading the old descriptions as universal current
gaps would repeat completed migrations; treating native source presence as
universal scientific qualification would be equally incorrect.

## Decision

Keep the baseline and add a separate source-revision-bound delivery snapshot
covering every baseline ID. Record scoped deliveries, retired versus remaining
Python scientific work, intentional compiler/oracle roles, tests to consult and
unmet acceptance. Keep the complete R0-R6 objective, even where one native owner
has already been delivered. Stable historical row IDs are not capability labels.

The existing ownership checker validates both artifacts. It checks complete
baseline membership, evidence paths and consistency of runtime classifications;
it does not infer dispatch from function-body text or permanently freeze an AST.
The audit SHA identifies the reviewed source, not a requirement for future HEAD
to retain byte-identical implementations. Evidence pointers are not test receipts.

## Rejected alternatives

- Rewrite the baseline as if it had always described current native delivery:
  that would erase the migration baseline and misrepresent its original revision.
- Infer full native support from merged PRs, energy registrations, linked source,
  or one wrapper test: none proves all installed contexts or derivative orders.
- Add another capability registry or source-body fingerprint gate: contextual
  admission and independent numerical evidence already have separate owners.

## Invariants

- All baseline rows and all R0-R6 requirements remain visible.
- A retained Python scientific controller prevents a native-only disposition.
- Symbolic compilation and independent references remain intentional Python work.
- Resource APIs and native source ownership do not certify whole-process memory,
  general response/HVP, new numerical domains, or endpoint performance.
- Native selected failure is distinct from missing-ABI compatibility admission.

## Evidence

The snapshot identifies source `9cfb77727661cc64e47938d9d0ba65a157427439`.
Dispatch inspection includes `PreparedBatch.execute`, the dedicated
`_native_hessian.py` frontend, native CLI resource ownership and the existing
native resource, policy and catalog consumers. Per-row test paths distinguish
host dispatch/refusal tests from independent numerical/device qualifications.
`tests/python/test_native_runtime_ownership.py` exercises coverage, provenance,
classification and evidence validation, not scientific endpoint acceptance.

## Revisit when

A remaining controller migrates or a scoped native domain changes. Refresh the
delivery revision and affected rows using actual dispatch and endpoint evidence;
do not update the original baseline SHA or mark #2227 complete from this audit.
