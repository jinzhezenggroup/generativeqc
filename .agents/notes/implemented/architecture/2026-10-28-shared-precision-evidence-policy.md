# Decision: share application precision evidence admission

Status: implemented
Date: 2026-10-28

## Problem

The native SCF owners publish physical-final checks and detailed operator/event
evidence, but the application facade repeated the decision about whether those
records justify budget-Fock, strict warm, or Standard fallback publication. SDK
consumers could not query the same policy. Missing work records also differ from
explicitly unavailable counters in the established fitted-HF fallback contract.

## Decision

Use one allocation-free native policy over the existing public provenance,
operator and event descriptors. Add a versioned context carrying model traits,
independently established gradient admission, budgets and the existing solver
controls/ceilings. Python translates its detached diagnostic records without
recomputing admission. Only a missing additive protocol selects the explicit
compatibility predicates; a native refusal remains authoritative.

Strict warm admission requires both the strict physical Fock and final audit to
refer to the exact returned owner, solve epoch and state generation. Pure-J mixed
proposals may retain actually observed strict J; hybrid/range/nonlocal operators
still require their own evidence. Unknown mixed-build counts cannot become zero.
Fitted HF retains its explicit unavailable-census exception without inventing
operator counts or an observable error certificate.

The additive SDK include is `generativeqc/precision_admission.h`, following the
existing separate Fock/optimizer extensions. Its declarations do not change the
widely included base descriptor header or force unrelated CUDA consumers to
recompile. Public-contract discovery and installation include the new header.

## Scope and retained owners

This is an R4/R6 policy cutover, not a native complete precision endpoint.
Solver-default selection, complete-model gradient qualification (including DF
and composite schema 4), candidate/auditor execution, numerical-only retries,
observable comparisons and independent bounded seed histories keep their current
owners. The public query cannot promote a new numerical domain and explicit
observable targets still run independent audits. R3 is unchanged.

## Validation

Executable public SDK and Python-consumer tests cover exact-state binding,
required full/range/nonlocal operators, missing versus unavailable census,
budget neighbours, malformed descriptors, transactional outputs and authoritative
native failures. Existing facade tests continue to protect scientific model,
gradient and audit semantics. Full endpoint qualification is recorded with the
change's final source/binary receipts before publication.

## Revisit when

The complete precision execution owner can retain candidate/audit/fallback plans
and their separate warm histories natively. Reuse these predicates there rather
than creating another interpretation of the same execution evidence.
