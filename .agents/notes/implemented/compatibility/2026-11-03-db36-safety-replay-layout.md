# Decision: preserve DB36 receiver bytes through isolated replay paths

Status: implemented
Date: 2026-11-03

The frozen DB36 H100 safety receivers refer to several sibling Git views and import other original receivers. Rewriting each receiver would change archived reader identities, including the composite proof's explicit reader hashes. The public wrapper instead reconstructs the original relative directory layout using the existing snapshot helper and local Git objects. It copies all14 original receiver/dependency files unchanged. Only named CPU receivers run; producer modules are imported for compiler-policy parsing, not executed as jobs.

Build metadata recovery expects its two original producer files already in place, so the wrapper authenticates and primes those exact files from the original archive before invoking the unchanged build receiver. The original spatial packet uses unpack-spatial-v2, and component/composite replay also requires the unchanged replay-spatial-v2 numerical helper. Failed packaging attempts exposed these dependencies before publication; they did not alter or rerun any GPU experiment.

The original spatial overall failure remains FAILED and its five partial race bodies supply zero accepted race coverage. Completed original normal6/memcheck6 and the separate successful unfiltered race6 produce only18 energy SCFs/54 source exports, not complete E+F or timing votes. The public stage reproduces seven original proof files exactly; profile/source7013 continuity and final-majority delivery remain separate scopes.

Both existing readers use the public read_evidence_bytes loader and authenticate the original cohort inventory. Current corrupt bytes never silently fall back. All four historical originals were recovered exactly before publication preparation.
