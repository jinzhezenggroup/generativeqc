# H100 small-CBS admission must survive bad metadata and process exits

Status: implemented bounded H100 evidence; complete32-slot matrix remains INCOMPLETE
Date: 2026-10-25
Refs: #2727, #2724

The small-CBS transport reuses frozen independent CPU/reference inputs and an
existing portable SM90 SDK. A host test being green does not establish that
the transport can safely spend a scientific attempt or independently accept
its returned numbers. V2 exposed four concrete counterexamples before any new
scientific calculation or resource submission.

First, the archived-water checker generated its composite oracle with the
coefficients in the native return. Setting those coefficients and the composite
E/F to zero still passed despite a 76.49197883990453-Eh error. V3 derives fixed
coefficients independently from the declared L/H=2/3, HF exponent 1.63 and MP2
exponent 3. Decimal exp and exact rational MP2 weights reproduce the model; the
returned weights only undergo a separate four-ULP metadata identity check.
Composite/L1 budgets never follow the returned weights. Semantic role/method/
basis mapping permits equivalent component reordering and preserves the shared
mp2_low/correction_mp2 roles. Original E/F thresholds do not change.

Second, the real CLI reports Job creation as a canonical decimal string. The
int-only V2 finalizer refused the actual wire value. V3 retains original JSON
bytes/type, adds a canonical comparison token, and requires a separately pinned
expected creation and submission window. It does not normalize the original
response or let that response establish its own expected creation identity.

Third, V2 serialized optional metadata before saving returned observables. A
synthetic native call returned complete E/F, then a metadata getter failed and
no IEEE original survived. V3 saves available composite/constituent E/F and
complete outer elapsed time before optional getters. Metadata enrichment is a
separate representation; original dtype/IEEE provenance is retained in the
minimal observable bundle. Metadata, I/O and identity faults halt later models
as transport/integrity failures. They cannot masquerade as a continuable native
numerical refusal. Missing values remain explicitly missing, never zero-filled.

Fourth, a real Linux host counterexample showed a command returning rc0 while
its same-group child remained live. V3 uses a fresh session/subreaper guard,
startup acknowledgement and actual PID/start-time/ancestry evidence. Only
freshly verified owned descendants receive pidfd signals. Clean command return
requires no remaining descendant; leader0 plus a live child is a control error
even when cleanup succeeds. Unknown ownership never authorizes a broad kill.
TERM grace, kill/reap and reporting are separately bounded and included in the
finite Job proposal. Existing shared services and outside sentinels are excluded.

The immutable V2 packet and all RED evidence remain retained. V3 host tests and
source-bound packet review precede any scientific release. Windows kernel skips
are not Linux lifecycle PASS. Actual H100 numerical acceptance, complete
precision/work telemetry, publication and protected delivery remain separate
evidence axes; this note establishes none of those later outcomes.

Revisit the algebra only with a separately identified model/fixture contract.
Revisit lifecycle handling only with executable ownership/cleanup evidence,
not a process leader's return code or an old PID/lock file.
