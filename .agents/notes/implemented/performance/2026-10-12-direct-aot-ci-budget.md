# Decision: give direct AOT qualification an independent cold-compile budget

Status: implemented
Date: 2026-10-12

## Problem and measured bounds

[CI run 38269101251](https://github.com/jinzhezenggroup/generativeqc/actions/runs/38269101251)
at PR #2366 head `9bc314d2841e713dd71f18abb2b093fe8777a662` stopped
[job 114886586476](https://github.com/jinzhezenggroup/generativeqc/actions/runs/38269101251/job/114886586476)
at its existing 25-minute whole-job limit. The direct J/K AOT shard-6 step began
at 15:52:53 UTC, after approximately eight minutes of setup and other release
validators, and was cancelled at 16:10:06. Its 1,500-second compiler timeout
could never fit in that remaining whole-job budget. The preceding f-shell,
XC, native grid, stationary and TensorIR gates passed. This was not evidence
of a compiler error or permission to relax the resource ledger.

The retained [direct AOT artifact](https://github.com/jinzhezenggroup/generativeqc/actions/runs/38269101251/artifacts/11758303975)
contains only the pre-compile compiler-cache receipt; its after status is
`not-recorded`. There is no completed object/compile-metadata pair to save.
`compile_shard` requires a passing receipt, matching identity/implementation/
compile context, and matching object and log hashes before accepting a hit.
This single NVCC object has no resumable partial compilation contract.

Five earlier canonical cold qualification steps took 720, 734, 629, 683 and
399 seconds in runs 38141692779, 38145917924, 38151179076, 38155416533 and
38157568655. Those are whole qualification-step durations for different
historical source checkpoints, not a fresh timing bound for the failed head.
The failed job spent 90 seconds on checkout and dependency installation, and
another 388 seconds on the preceding resource tier and its configure work.

## Decision

Move direct AOT configure, restore, qualification, save and retained reports
into one independent required `cuda-direct-aot` job. Keep the same exact event
commit, canonical production build/generated paths, ccache 4.14 launcher,
release recipe, source/toolchain identities and fail-closed ledger comparison.
The existing resource job retains all its other gates, once each.

Both resource jobs keep a 25-minute whole-job ceiling. The direct compiler
receives 1,200 seconds; its enclosing step receives 22 minutes. This provides
time for the compiler owner to terminate its process group and write failure
receipts, and leaves measured setup/report headroom. Unusually slow setup or
code generation can still exhaust the outer deadline: this is bounded work,
not a guarantee that every cold compile passes.

`Pass CI checks` includes the new job's result and permits neither its failure
nor its skip. Existing orphaned merge-group handling remains unchanged.
Diagnostics retain their original artifact names, paths and retention policy.

## Cache transport and trusted seeding

The live cache API at 16:31 UTC returned nine `direct-jk-aot-12.9-sm120-`
snapshots, all scoped to `refs/pull/*/merge`, and no default-branch snapshot.
Neither the CPU master producer nor the native CLI ccache artifact owns this
validator's object/log/metadata cache. The new direct job therefore also runs
on pushes to `refs/heads/master`, without adding any other resource validators
to master pushes. Tags and non-master pushes remain excluded. PR/manual/nightly
admission and merge-group no-write policy remain unchanged. A failed compile
or ledger comparison still cannot publish a complete snapshot.

There was also a reproducible transport-key defect: the broad compiler `/**`
globs were evaluated after Python imports and included generated bytecode.
All 231 tracked direct-key inputs are identical on master `ef225164`, PR #2366
and PR #2374, but those jobs had different transport keys. A local reproduction
with the real `@actions/glob@0.5.0` implementation demonstrates that adding
`.pyc`, and then changing only its timestamp header, changes the old hash with
unchanged source. `.gitignore` does not exempt those matching files.

All five resource-cache keys now explicitly exclude `__pycache__`, `.pyc` and
`.pyo`. The same real glob implementation keeps a stable hash across those
bytecode changes and still invalidates on a source edit. Source/header/tool
patterns and fallback prefixes remain intact; only disposable derived bytecode
is excluded. See the upstream [hash implementation](https://github.com/actions/toolkit/blob/main/packages/glob/src/internal-hash-files.ts).

The direct transport key also includes `CMakeLists.txt`, which the inner cache
already includes in `COMPILE_IMPLEMENTATIONS`. Previously a CMake-only change
could restore an exact immutable outer key, cause a legitimate inner miss,
compile a new object and then skip saving it because `cache-hit` was true.
Aligning that missing transport input prevents this stale-exact-hit trap.
No inner identity, ledger or object/log validation is relaxed or modified.

## Rejected alternatives

- Raising the entire serial resource job budget leaves unrelated validators on
  the cold direct shard's critical path and masks the mismatched deadlines.
- Saving interrupted direct objects cannot recover work: an incomplete object
  and absent passing metadata are deliberately not cache hits.
- Fast compilation, another split-compile setting, another generated path or
  weakened cache identity would describe a different resource qualification.
- Dropping resource checks, allowing failures/skips or cancelling other CI
  changes correctness rather than repairing scheduling.

## Verification and limits

Workflow-graph tests protect liveness, exact-event checkout, once-only gate
ownership, finite inner/outer budgets and retained failure receipts. Aggregate
controls exercise success/failure/cancel/skip across required events and reject
mutations that omit or exempt the new job. Existing direct-ledger tests retain
object/log identity, compiler-context and timeout/failure controls.

A one-off parsed-workflow comparison verifies the relocation and leaves
unrelated jobs, top-level trigger/security/concurrency settings and scientific
resource semantics unchanged. The only job-admission extension is the bounded
master-only seed described above. No CUDA compiler or GPU execution is claimed locally. Hosted cold
and warm outcomes remain the acceptance evidence for elapsed-time/cache gains.

## Consequences and revisit conditions

Independent execution adds one runner and repeats the small dependency setup;
it avoids repeating completed sibling validators when only the direct job needs
a retry. Successful master snapshots can amortize the expensive object across
PRs and queue refs, while unchanged inner identities remain replayable. The
tradeoff is justified by the failed job's measured serial delay and verified
absence of a shared direct snapshot.
Revisit if hosted direct cold compiles exceed the finite budget, setup becomes
material, or the production shard/compile context deliberately changes.
