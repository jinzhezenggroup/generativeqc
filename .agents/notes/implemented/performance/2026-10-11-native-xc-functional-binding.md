# Decision: bind admitted equal-spin XC consumers before native register allocation

Status: implemented local opt-in lowering; endpoint promotion pending
Date: 2026-10-11

## Problem

The [equal-spin scalar-sharing candidate](2026-10-11-equal-spin-xc-scalar-sharing.md)
removes redundant spin DAG work, but its native feature-width specialization
still receives a runtime functional. Compiling all GGA or MGGA consumers into
one device function retains unrelated algebra in the register-allocation scope.
Isolated method-bound scalar throughput therefore overstates what scalar
sharing alone establishes for the native SCF consumer.

## Decision

Keep the incumbent kernels unchanged. On the opt-in, producer-proven RKS route,
resolve the existing functional code on the host and instantiate
`evaluate_points<feature_terms, false, batched, true, functional_code>`.
The bound code selects the canonical emitted point algebra; the producer binds
both spin channels to the same half-density/gradient/tau source. Reject a wrong
spin layout, unknown code or incompatible feature width before launch.
Single-tile and compact-batched kernels use the same guarded dispatcher.

Generate the code/width projection for registered split hybrids alongside their
existing XC registry, from the same validated manifest entries. The small DFT
metadata module carries only launch bindings, not scientific expressions,
method composition or admission policy. This preserves the established
dependency direction: XC can consume DFT ingredients, but DFT cannot import XC.
An initial direct import of the XC metadata failed both the structure audit and
the existing fresh-process no-XC-import regression; do not weaken those gates.

## Invariants

- Differentiate before spin binding; keep independent polarized partials and
  the cross-sigma lane, work-input screens, floors and energy rescaling.
- Do not widen backend/method admission or select on a descriptive method label.
- Keep UKS, response, stationary force points and LDA/PBE on their original
  paths. Unset/`0` remains the bounded incumbent; `1` is experimental.
- Do not introduce a resident-storage precondition, buffer or CPU/reference work
  in production execution.
- Keep the projected table generated and freshness-checked against its one
  authoritative registry, rather than maintaining hand-written numeric codes.

## Rejected alternatives

- Feature-width-only equal-spin specialization: it leaves runtime dispatch and
  unrelated scientific algebra inside the allocation scope.
- Bind all incumbent/UKS/response consumers simultaneously: that expands AOT
  inventory and qualification scope before this restricted candidate is proven.
- Duplicate formulas, omit derivative lanes or relax precision/work thresholds
  to reduce registers: these change the scientific contract.
- Import XC into DFT, or exempt this new edge from the structure checker: the
  generated launch metadata projection satisfies the requirement without a
  dependency cycle or a second source of scientific truth.

## Consequences and remaining qualification

This adds per-functional candidate kernels and generated binding metadata,
increasing AOT inventory. Compile duration, binary size, complete cold/warm/moved
E+F timing, semantic work and independent molecular energy/force gates remain
mandatory before default promotion. Keep failed and incomplete cohorts.

The current method resolver admits WB97M-V, but rejects bare WB97, WB97X,
WB97X-D and WB97X-V. Their dispersion parameter names do not prove executable
range-separated method admission. The full-family objective remains open;
do not claim that specializing WB97M-V optimizes every wB97 composition.
r2SCAN scalar work likewise does not qualify the prescribed r2SCAN-3c basis,
D4, gCP and complete endpoint.
