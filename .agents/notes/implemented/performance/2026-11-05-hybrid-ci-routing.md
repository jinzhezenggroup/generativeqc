# Decision: isolate new hybrid qualification files from historical core slots

Status: implemented
Date: 2026-11-05

## Problem and evidence

PR #2977 head `021ad2ff92076060ec2dea22522146cd6230bead` adds eleven Python
qualification files relative to base `4478c16c15f8c55b5cb2616906a97ea1f5673b57`.
The existing sorted-file modulo router moves 1292 of 2163 existing core files
when these files are inserted. Probe compiler caches are shard-specific.

Run 42017101273 reports 1426.82 aggregate worker-seconds for twelve molecular
Hessian/HVP cases, 212.86 worker-seconds for two lifecycle cases, and 399.61
seconds for the complete d/f nuclear-attraction weighted HVP. These are not
wall-clock savings or a controlled base/head endpoint benchmark. All three
core jobs report that no probe overlay could be restored, including prefix
fallback, so their low cache hit rates cannot be attributed solely to routing.

## Decision

Give these eleven files explicit supplemental core owners without consuming
ordinary modulo slots. Preserve their current head owners: the complete
molecular matrix uses core-c worksteal, the d/f source test core-a, and lifecycle
tests core-b. This separates the three major added workloads while restoring
every prior file's base owner and relative order. Do not change any scientific
case, marker, deselection, distribution mode, worker count, or cache policy.
Only tracked paths participate; missing tracked paths remain selected so an
incomplete checkout fails rather than silently omitting qualification.

## Alternatives and limits

Do not move the molecular file to the existing loadfile compiler-heavy shard:
its twelve independently runnable cases could become a roughly 24-minute
single-worker tail. Do not delete independent matrix/curvature or lifecycle
gates. A repository-wide hash router would move many existing files again and
is outside this targeted correction. This change does not stabilize arbitrary
future files, solve unavailable cache restores, or establish a CI speedup.

## Verification

Execute the actual Bash selector for all eight shards and five events
(pull_request, push, merge_group, schedule, workflow_dispatch). Against the
current base, the patched inventory is the original 2260 files plus all eleven
new files exactly once. Every original file retains its owner and relative
order; coverage, exclusions, scheduling options, and distribution are unchanged.
Permanent regressions exercise absent, untracked, tracked, and missing tracked
qualification paths without relying on repository history or source hashes.
All 1316 shard-ownership and native-probe-cache regressions pass in 94.95 s
in a local pytest/xdist environment; Bash syntax and Ruff checks also pass.
No C++ or molecular numerical code changes, so this is routing validation,
not a new scientific endpoint timing receipt.

## Revisit when

Use fresh JUnit timing and cache-restore evidence to rebalance if a new critical
path appears. A later general stable-router migration needs its own baseline
and must retain complete coverage and cache trust boundaries.

## Probe-cache transport correction

The latest PR run restored no probe overlay, even by prefix. Old snapshots that
were successfully saved around 06:00 UTC were absent from the cache API at
12:16; surviving entries totaled 9.08 GiB and three CUDA/wheel snapshots occupied
about 8.13 GiB. Capacity eviction is consistent with this evidence but its deletion
actor is not publicly recorded. The small probe cache's own 256-MiB limit was
not exhausted. The subsequent merge queue could not see still-existing PR
snapshots because they belonged to `refs/pull/2977/merge`; no master probe cache
was available. Same-source PR/queue trees also produced different broad
post-build `hashFiles` keys, which include generated checkout files.

Capture a fingerprint of sorted committed path/mode/blob records after the
README-only scope classifier and before build/test environment preparation. Generated bytecode, working-tree assets and commit metadata do not
change this transport key. Committed relevant source additions, edits, renames,
deletions and mode changes do. ccache still validates actual compiler inputs;
this transport fingerprint never replaces scientific or native artifact identity.

Reuse the existing scheduled/manual master Python qualifications to publish
separate, bounded per-shard probe artifacts. Do not add a second full test matrix
on push. After a true primary-cache miss, consumers may restore only a verified
successful canonical-master qualification from the expected workflow/event,
repository IDs, source SHA, run/attempt, artifact name and digest. Restore only
cache data into the otherwise absent probe directory; never import PR artifacts
or probe overlays into the shared CPU compiler cache. Optional failures remain
bounded cold compilation. Existing CPU/wheel provenance rules stay unchanged.

The first usable baseline requires a subsequent successful master nightly/manual
qualification. This patch alone cannot claim a warm-cache run or measured speedup.
No cache deletion, storage-limit change, workflow dispatch, cancelled CI, or
scientific test reduction is part of this correction.

Local transport validation additionally passes 164 probe-profile security cases
and 146 existing CPU/wheel snapshot regressions. Fingerprint tests exercise real
Git inventories, including generated bytecode, committed source changes and
same-tree commits. Producer/fallback workflow-condition matrices reject PR,
queue, fork, non-master, failed and skipped publication paths as appropriate.

The first PR CI run exposed an omitted workflow-contract regression: the new
fingerprint step preceded README-only classification and artifact publication
lacked an explicit prose guard. Move fingerprinting after classification, before
environment/build preparation, and apply the existing prose guard to both new
steps. Preserve the original prose tests unchanged and run the complete CI
contract suite as well as the focused cache tests. No running CI is cancelled.
The same run exposed a second pre-existing CI-key assertion in the DF shell-unit
suite that required literal hashFiles globs for every cache. Keep that check for
all unchanged cache families; bind probe keys to their actual committed-input
producer instead. New real-Git tests verify that committed CMake and compiler
source changes invalidate the probe fingerprint, preserving the intended guard.
