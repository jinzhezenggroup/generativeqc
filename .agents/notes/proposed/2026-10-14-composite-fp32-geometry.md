## Ownership boundary

The native full-range controller cannot authenticate an RSH/VV10 or DF source
inventory merely by adding another point code. Instead, the existing composite
owner can explicitly request the already-emitted typed geometry consumer for
its semilocal accumulator. A versioned resident-weight entry borrows the exact
current density generation/paired-feature proof and fails on stale or missing
proofs. External nonlocal seeds never use it. Mathematical expressions remain
owned by the shared compiler; no second WB97M-V or partition formula is added.

`fp32_semilocal_geometry=True` is a private diagnostic parameter, not public
method admission or a user-facing kernel-selection policy. The execution
identity includes this parameter so retained owners cannot silently reuse the
opposite arithmetic. SCF, AO production, integral/range derivatives and VV10
remain strict. Point conditioning/tails and final reductions also retain their
existing FP64 boundaries. This is deliberately not called all-FP32 WB97M-V.

The native source owner reports cumulative FP32-candidate geometry batches and
points. Delta records describe actual enqueued work, not the number of points
whose guarded XC interior actually used float; unsafe tails may widen. Metrics
are not successful numerical publication until the normal complete-source
drain, reduction and live-state validation pass. A missing metric is not zero.

## Bounded recovery

Numerical source failures now have native status 5, distinct from invalid
contracts (1), allocation (2/3) and CUDA runtime failures (4). The Python source
owner preserves these distinctions. Existing nonzero-rejection/native wrappers
remain compatible. An explicit candidate may retry the complete gradient once
in FP64, only after positive actual mixed work and a typed numerical failure.
It closes/drains every rejected source before rebuilding at the same live
state. Driver, identity, capability and allocation failures never trigger this
retry. Failed strict retries publish nothing. The work record includes rejected
attempts and the complete elapsed cost rather than charging only the successful
strict attempt.

## Recovery exposed a real lifetime defect

Slurm 8330 passed all four independent numerical cases (24/96-AO spherical
water, ammonia, Cartesian water), then **segfaulted in the injected pre-drain
failure**, before timing. Do not describe that suite as passed. The source
accumulators were registered before their grid producer in the ExitStack, so
unwinding destroyed the grid/borrowed stream before pending consumers called
`stationary_destroy`. Ordinary fully drained success hid this lifetime error.

Registering the producer first reverses destruction into the required consumer
then producer order. No synchronization, numerical tolerance or failure test was
removed. Slurm 8335 passed the same real pending-work recovery and failed-peer
test: all rejected work is drained, the complete strict replay matches the
independent oracle, and the following call resumes mixed work. The focused host
owner/recovery checks passed 40 tests after this change; the broader host suite
passed 367 before it. All-followup pre-commit passed before the final cleanup
ordering edit and new notes. Final full scheduled regression/timing remains
distinct from these partial receipts.
